# PROMPT.md — план работ и готовые промпты для Claude Code

> **Как этим пользоваться.** Не отправляй Claude Code весь этот файл разом.
> Копируй по одному блоку «ПРОМПТ ФАЗЫ N» за сессию. Между фазами — коммит и `/clear`.
> Правила поведения агента лежат в `CLAUDE.md` (читается автоматически).
> Требования — в `SPEC.md`.

---

## Почему пофазно, а не «сделай всё сразу»

Одна огромная инструкция → агент теряет детали в середине, генерирует правдоподобный, но нерабочий код, и ты получаешь 60 файлов, которые не компилируются и которые невозможно отладить, потому что непонятно, где сломалось.

Одна фаза = один работающий, собирающийся, закоммиченный результат. Если фаза сломалась — откатываешь один коммит, а не весь проект.

## ФАЗА 0 — Подготовка окружения (делаешь ты, не агент)

Скелет проекта **не должен** генерировать модель по памяти: версии Loom/Yarn/Loader меняются, и это самый частый источник «не собирается».

1. Открой https://fabricmc.net/develop/template/
2. Заполни: Mod name `TickPilot`, Package `com.tickpilot`, Mod ID `tickpilot`,
   Minecraft `1.21.1`, Kotlin — нет, **Split client/server sources — ДА**,
   Data generation — нет (не нужно).
3. Скачай zip, распакуй в папку `tickpilot`.
4. Проверь, что скелет собирается **до** того, как пускать туда агента:
   ```bash
   cd tickpilot
   ./gradlew build        # Windows: gradlew.bat build
   git init && git add -A && git commit -m "chore: fabric template baseline"
   ```
5. Положи рядом `CLAUDE.md`, `SPEC.md`, `PROMPT.md`.

Если `./gradlew build` не прошёл на пустом шаблоне — проблема в окружении (JDK, сеть, прокси), и никакой агент это не «допишет». Чини сначала это.


## ПРОМПТ ФАЗЫ 8 — Зоны активности и осторожные политики (FR-7, FR-8, FR-9, FR-11)

```
Фаза 8. Самая рискованная фаза. Действуй консервативно.

Требования: SPEC FR-7, FR-8, FR-9, FR-11, INV-5, INV-8, AC-7.

   Реальный throttling — исключительно для типов из throttle_allowlist,
   denylist имеет приоритет над allowlist.
4. Никогда не менять частоту полного Entity.tick() там, где это может сломать физику,
   коллизии, езду, поводок или следование за игроком.
5. Unit-тесты на выбор зоны и на то, что STRICT блокирует все политики.

Если для безопасного разрежения нет корректной точки внедрения — оставь только
метрики и напиши мне об этом прямо. Не имитируй работающую оптимизацию.

```
